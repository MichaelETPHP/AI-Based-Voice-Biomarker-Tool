Voice Biomarker API · v1

Add voice-based mental health screening to your application

Send 30 seconds of English speech. Get back screening signals for depression and anxiety, derived from how a person speaks: tone, energy, rhythm and pauses, not the words. Powered by the open-source Kintsugi Health DAM model.

Quickstart API reference
01

Record

Capture 25–40 s of natural English speech from one person, saved as a WAV file.

02

Send

POST the WAV to /v1/analyze with your API key, from any backend or integration platform.

03

Receive

Get levels, raw scores and a screening signal as JSON in about 5–15 seconds. The audio is deleted immediately.

Base URL for this server: {{BASE}}. All endpoints are versioned under /v1.

Quickstart

  1. Request an API key with the request form. Requests are reviewed and the key is sent to you by email.
  2. Check the service is up. It needs no key: 
    curl {{BASE}}/v1/health
  3. Analyze a recording (recording.wav: 16-bit PCM, mono, 25–40 s): 
    curl -X POST {{BASE}}/v1/analyze \
  -H "Authorization: Bearer $VOICE_API_KEY" \
  -H "Content-Type: audio/wav" \
  --data-binary @recording.wav \
  --max-time 120
  4. Read the result: depression.level, anxiety.level and the screen signal. See Response fields.

Authentication

Every request except /v1/health and /v1/openapi.json needs an API key (request one here). Send it in one of these headers:

Authorization: Bearer YOUR_API_KEY
# or
X-API-Key: YOUR_API_KEY
Keep keys on the server. Never put an API key in a mobile app, browser JavaScript or a public repository. Call this API from your backend, an integration platform (MuleSoft, AWS, Salesforce) or a secrets-backed function. Store the key in a secrets manager such as AWS Secrets Manager, a Salesforce Named/External Credential or MuleSoft secure properties.

Audio specification

The model was trained on short, natural English speech. Recordings outside this specification are rejected with a clear error, or produce unreliable results.

PropertyRequirement
Container / encodingWAV, 16-bit PCM (signed little-endian)
ChannelsMono (1 channel)
Sample rateAny rate. It is resampled to 16 kHz internally, so 16 kHz is ideal.
Duration25–40 seconds for /v1/analyze (30 s recommended); 3–40 s for /v1/language
SizeMaximum 10 MB (30 s at 16 kHz is about 1 MB)
ContentOne speaker, English only, natural speech (for example "describe your day"), little background noise
How to sendRaw body with Content-Type: audio/wav (recommended), or the multipart form field audio

Convert other formats (m4a, mp3, ogg, stereo) with ffmpeg:

ffmpeg -i input.m4a -ac 1 -ar 16000 -sample_fmt s16 -t 35 recording.wav

Analyze voice

POST/v1/analyze

Checks that the speech is English, then runs the DAM model. Returns depression (3 levels) and anxiety (4 levels) results with raw scores and a binary screening signal. Typical time: 5–15 s.

Request

PartValue
HeaderAuthorization: Bearer <key> or X-API-Key: <key>
HeaderContent-Type: audio/wav (raw body) or multipart/form-data
BodyThe WAV bytes, or a multipart field named audio
Optional headerX-Request-ID: your own correlation ID, echoed back in the response
 
# Raw WAV body (recommended)
curl -X POST {{BASE}}/v1/analyze \
  -H "Authorization: Bearer $VOICE_API_KEY" \
  -H "Content-Type: audio/wav" \
  --data-binary @recording.wav \
  --max-time 120

# Or multipart form upload
curl -X POST {{BASE}}/v1/analyze \
  -H "Authorization: Bearer $VOICE_API_KEY" \
  -F "audio=@recording.wav;type=audio/wav"

Language check

POST/v1/language

Detects whether 3–40 s of audio is English speech, without running the depression and anxiety model. Use it to validate a recording, or to stop a live recording early. /v1/analyze runs this check automatically and returns 422 not_english when it fails.

curl -X POST {{BASE}}/v1/language \
  -H "X-API-Key: $VOICE_API_KEY" \
  -H "Content-Type: audio/wav" \
  --data-binary @first-10-seconds.wav
{ "language": "en", "language_name": "English", "confidence": 0.9936, "english_prob": 0.9936, "is_english": true }

Response fields

FieldTypeMeaning
depression.levelinteger0 none (PHQ-9 0–9) · 1 mild to moderate (10–14) · 2 severe (15+)
anxiety.levelinteger0 none (GAD-7 0–4) · 1 mild (5–9) · 2 moderate (10–14) · 3 severe (15+)
*.labelstringPlain-English description of the level
*.rawnumberRaw model score; higher means more signs. Use it for trends over time.
*.thresholdsnumber[]The score cut-offs between levels (official model thresholds)
*.screen.resultstringpositive (likely questionnaire score ≥ 10) · negative (unlikely) · indeterminate (grey zone, so re-record)
*.screen.sensitivity / specificitynumberMeasured on the public KintsugiHealth/dam-dataset test split (about 71–75%)
languageobjectDetected language and the probability that it is English
duration_s / elapsed_snumberAudio length and server processing time
Which field should I use? For a yes/no follow-up decision, use screen.result. To show severity, use level. To track a person over time, use raw.

Errors

Errors use standard HTTP status codes and always return JSON with a machine-readable error and a human-readable message:

{ "error": "bad_duration", "message": "The recording is 12.0 s long. Please record about 30 seconds (25-40 s)." }
StatuserrorCause and what to do
400missing_audioNo audio in the body or in the audio field
400invalid_wavNot a 16-bit PCM mono WAV. Convert it with ffmpeg.
400bad_durationOutside 25–40 s (/v1/analyze) or 3–40 s (/v1/language)
400silentNo audible speech. Check the microphone.
401unauthorizedMissing or invalid API key
413too_largeLarger than 10 MB
422not_englishThe speech is not English (response includes language_name). Re-record in English.
429rate_limitedHourly limit for your key reached. Retry later with backoff.
500analysis_failedUnexpected failure. Retry once, then contact support with the X-Request-ID.
503busyThe server is at capacity. Retry after a few seconds (exponential backoff).
503model_not_loadedThe server is starting up. Retry in a minute.
503api_not_configuredNo API keys are configured on the server yet. Contact the administrator.
Retry policy: retry 429, 503 and network errors with exponential backoff (2 s, 4 s, 8 s…). Don't retry other 4xx errors; fix the request instead.

Rate limits & timeouts

  • Per-key limit: 200 requests per hour by default (configurable by the administrator). After that you get 429.
  • Processing: analyses run one at a time per server. When the queue is full you get 503 busy.
  • Timeouts: set your client timeout to at least 120 s. Typical responses take 5–15 s.
  • Tracing: every response has an X-Request-ID header. Log it next to your own records.

MuleSoft (Mule 4)

Import the OpenAPI spec into Anypoint Exchange / Design Center to generate a REST connector with REST Connect. You can also call the API directly with the HTTP Request connector. The flow payload must be the WAV bytes, for example from the File, SFTP or Amazon S3 connector.

<!-- config.yaml: voice.host=your-domain.example ; voice.apiKey in secure properties -->
<http:request-config name="Voice_API_Config">
  <http:request-connection protocol="HTTPS" host="${voice.host}" port="443" />
</http:request-config>

<flow name="analyze-voice-flow">
  <!-- payload = WAV bytes -->
  <http:request method="POST" config-ref="Voice_API_Config"
                path="/v1/analyze" responseTimeout="120000">
    <http:headers><![CDATA[#[{
      "Authorization": "Bearer " ++ p('secure::voice.apiKey'),
      "Content-Type": "audio/wav",
      "X-Request-ID": correlationId
    }]]]></http:headers>
  </http:request>

  <ee:transform>
    <ee:message><ee:set-payload><![CDATA[%dw 2.0
output application/json
---
{
  depressionLevel: payload.depression.level,
  anxietyLevel:    payload.anxiety.level,
  followUp:        payload.depression.screen.result == "positive"
                   or payload.anxiety.screen.result == "positive"
}]]></ee:set-payload></ee:message>
  </ee:transform>

  <error-handler>
    <!-- HTTP:TOO_MANY_REQUESTS / HTTP:SERVICE_UNAVAILABLE -> retry with until-successful -->
    <on-error-propagate type="HTTP:BAD_REQUEST, HTTP:UNAUTHORIZED">
      <logger level="WARN" message="#[error.errorMessage.payload.message]" />
    </on-error-propagate>

AWS (Lambda)

This example analyzes every WAV uploaded to an S3 bucket. It uses Python 3.12 with no extra libraries. Set the Lambda timeout to 2 minutes, and store the key in AWS Secrets Manager or an encrypted environment variable.

import json, os, urllib.error, urllib.parse, urllib.request
import boto3

s3 = boto3.client("s3")
API = os.environ["VOICE_API_URL"]          # {{BASE}}
KEY = os.environ["VOICE_API_KEY"]          # or fetch from Secrets Manager

def handler(event, context):
    rec = event["Records"][0]["s3"]
    bucket = rec["bucket"]["name"]
    key = urllib.parse.unquote_plus(rec["object"]["key"])
    wav = s3.get_object(Bucket=bucket, Key=key)["Body"].read()

    req = urllib.request.Request(
        f"{API}/v1/analyze", data=wav, method="POST",
        headers={"Authorization": f"Bearer {KEY}", "Content-Type": "audio/wav"},
    )
    try:
        with urllib.request.urlopen(req, timeout=120) as resp:
            result = json.load(resp)
    except urllib.error.HTTPError as e:
        result = {"status": e.code, **json.load(e)}   # {"error": ..., "message": ...}

    # e.g. save next to the recording
    s3.put_object(Bucket=bucket, Key=key + ".result.json",
                  Body=json.dumps(result).encode(), ContentType="application/json")
    return result

Other AWS options: Step Functions (an HTTP task calling the Lambda), EventBridge API Destinations (the key as a connection header), or importing the OpenAPI spec into API Gateway as a managed proxy.

Salesforce (Apex)

  1. In Setup, create an External Credential with a principal parameter ApiKey, and a Named Credential Voice_Biomarker_API with URL {{BASE}}.
  2. Add a custom header to the Named Credential: Authorization = Bearer {!$Credential.Voice_Biomarker_API.ApiKey}.
  3. Call it from Apex. The recording is a File (ContentVersion), for example one uploaded from a Lightning page or Experience Cloud.
public with sharing class VoiceBiomarkerService {

    public static Map<String, Object> analyze(Id contentVersionId) {
        ContentVersion cv = [SELECT VersionData FROM ContentVersion WHERE Id = :contentVersionId LIMIT 1];

        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:Voice_Biomarker_API/v1/analyze');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'audio/wav');
        req.setBodyAsBlob(cv.VersionData);   // ~1 MB for 30 s at 16 kHz
        req.setTimeout(120000);              // Apex maximum (120 s)

        HttpResponse res = new Http().send(req);
        Map<String, Object> body = (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
        if (res.getStatusCode() != 200) {
            throw new CalloutException(body.get('error') + ': ' + body.get('message')
                + ' (request ' + res.getHeader('X-Request-ID') + ')');
        }
        return body;   // body.get('depression') -> Map with level, label, raw, screen
    }
}
Apex callouts can't run directly in triggers. Use a Queueable with Database.AllowsCallouts or @future(callout=true). Synchronous Apex has a 6 MB heap limit, which is fine for 30 s recordings.

Responsible use

Research prototype, not a medical device. Results are screening signals, not a diagnosis. Always show this to end users and direct them to a qualified health professional. Never make clinical decisions from this output alone.
  • Consent: get the speaker's explicit consent before recording and analyzing their voice.
  • English only, one speaker: other languages are rejected (422). Accuracy for accents and groups under-represented in the training data is not established.
  • Privacy: this server deletes audio immediately and stores no results. Your own storage of audio and results must follow the laws that apply to you (for example GDPR or HIPAA).
  • Crisis situations: if a user may be in danger, show local emergency and helpline contacts in your own interface.
  • Attribution: uses the open-source DAM model by Kintsugi Health (Apache-2.0). Not endorsed by Kintsugi Health.

Server administration

For the owner of this deployment. Set these in .env next to docker-compose.yml, then run docker compose up -d.

# One key per client application ("name:key", comma-separated). Names appear in the logs.
API_KEYS=mulesoft-prod:4f9c...e1,aws-pipeline:a83b...77,salesforce:90d2...c4

# Optional: browser apps on these origins may call /v1 directly
CORS_ORIGINS=https://app.example.com

# Requests per hour per key (default 200)
RATE_LIMIT_API_PER_HOUR=200

When a key request arrives by email: review the use case, generate a key, add client-name:KEY to API_KEYS, restart the app, and reply to the requester with the key over a secure channel.

Generate a strong key with openssl rand -hex 32. To revoke a key, remove it and restart. Without API_KEYS, the public API is disabled in production (503 api_not_configured), and the web app keeps working.
